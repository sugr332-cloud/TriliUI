## 上流機能を取りこぼさない棚卸し手順
1. 対象Triliumのタグを固定。原典README、ガイドのサイトマップ、ノートタイプ登録リスト、UI menu/command registry、設定画面、キーボードショートカット一覧、ETAPI仕様を列挙し、文書URLとソース行を保管。
2. 同じタグのTriliumをPCブラウザで起動、ナビゲーション、ノート種別作成、コンテキストメニュー、上部ツールバー、設定画面、インポートエクスポート、共有、スクリプト、管理画面を全画面ウォークスルー。
3. Androidモバイルでも同じ棚卸し。「Androidの上流に無い」場合はTriliUI側で操作可能な代替UIを指定。
4. メニュー/コマンドをFIDへ1対1または1対多で関連付け。未対応のコマンドがゼロになるまで全体の完了は不可。
5. 上流版更新で追加/削除/仕様変更された操作をdiffし、FIDと回帰試験を更新。
6. 実装可否は、公式フロントエンドAPI→既存画面の再利用→内部UIへの局所拡張→権限を絞ったサーバー側の補助、の順でPoC。不可の場合は理由、証拠、代替UI、再検討条件を明文化。

## テストフィクスチャ
- 3階層×複数親へのクローン、ルート/枝の並べ替え、50文字以上の日本語タイトル
- HTMLリッチテキスト: 表、画像、リンク、数式、チェックボックス、Markdown自動整形
- text/code/canvas/mermaid/relation-map/note-map/mind-map/geo-map/book/webview/collection/render の版対応サンプル
- 10件の属性・関係、テンプレ継承、保存検索、保護ノート、日付ノート、外部添付PDF
- 権限不足、切断、応答遅延、無効ノートID、トークン不一致、DOMセレクタ変化の故障注入
- 1k、10k、50k、100k件のデータはそれぞれ独立生成し計測条件を記録

## 標準E2Eテンプレート
`FID-A-P`: Android Chrome実機、サーバー/タグ記録→操作を開く→対象機能の全操作→保存→ページ再読込→PCで結果一致→Android横向きで再確認→意図的エラーと復旧を記録。スクリーンショット（機密除去）とテストログを添付。

## 品質ゲート
- PRに追加・変更FIDの一覧、動作する前後の画面、E2E、リグレッション、解除手順を添付。
