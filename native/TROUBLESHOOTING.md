# TriliUI Phase 1 — Android 実機診断手順（v0.1.1）

## 前提：全項目が「未確認/失敗」でも、故障とは断定しない

5項目が全部未チェックの場合は、まず**導入済みかどうか**、実際に画面が崩れたか、まだ操作していないかを切り分ける。推測でリポジトリ本体をマージしない。

## 準備

1. Trilium のノートをバックアップし、元のノート本文は変更しない。
2. **[最新版のスクリプト](./triliui-mobile-startup.js)** 全体をコピー（以前貼り付けたものは全部置換）。
3. Trilium に `TriliUI Mobile Startup` という **Code** ノートを作成して **JS (frontend)** に変更する。コード全体を貼り付ける。
4. 属性（Attributes）に **ラベル名 `run`、値 `mobileStartup`** を付ける。画面表示は `#run=mobileStartup`。
5. Android Chrome を再読み込み。Trilium 標準のモバイル画面になっていることをまず確認。必要なら Trilium のグローバルメニューで **Switch to Mobile Version** を選ぶ（`?mobile` の指定はログインページで行う）。
6. Android Chrome で Trilium のURLに `?triliuiDebug=1` を付けてアクセス（URLにすでに `?` があれば `&triliuiDebug=1`）。ログイン済みの画面からアクセスする。

## 左上/右上の診断バナーを読む

診断バナーは **TriliUIが起動したときだけ** 表示される。Trilium公式の診断機能ではない。

| バナーの内容 | 意味 | 対処 |
|---|---|---|
| **TriliUI 0.1.1 \| ready** | 起動スクリプト実行済み、必要なDOM要素を検出し、CSSと☷ボタンを追加済み | 左ツリーと右本文、☷ボタンを実際に確認 |
| **waiting-for-mobile-class** | 実行はされたがTriliumに `body.mobile` がまだ無い | ページがモバイル版か確認。15秒以上ならバージョン・表示モードを確認 |
| **waiting-for-layout \| missing: ...** | スクリプト実行済み、必要な Trilium DOM 部品の一部がまだ無い | しばらくして自動遷移するか確認。変わらなければDOMの変更を疑う |
| **timed-out** | 15秒以内に起動条件が揃わない | Triliumのバージョンと診断表示、スクリーンショットを記録 |
| **desktop-skipped** | Triliumのbodyが desktop 判定 | グローバルメニューからモバイルに切り替える |
| **バナーそのものが表示されない** | スクリプト未実行、古いコード、緊急停止が有効、または表示以前に例外 | 下記「バナーが出ないとき」の手順へ |

バナーは実行時にだけ表示されるので、`?triliuiDebug=1` を付けた後は必ず**ページの再読み込み**を行う。URLパラメーターはTrilium本体のコマンドではなく本スクリプト専用。

## バナーが出ないとき（最短切り分け）

1. Trilium自体は開いているか？ Androidのモバイル画面か？
2. ノートが **Code / JS (frontend)** か？ JS (backend) ではないか？
3. 属性は `#run=mobileStartup` **ひとつのラベル**か？ `frontendStartup` ではないか？
4. スクリプトは v0.1.1 の**全コード**を貼り付けたか？（一部のみの貼り付けでは不可）
5. `?triliuiOff=1` がURLに残っていないか？
6. いったん `#run` 属性を外して、別の Code / JS (frontend) ノートを作り、以下の**手動起動テスト**をする：

```js
api.showMessage("Trilium JS (frontend) を実行しました");
```

そのノートの **Execute / 実行** からトーストが出るか確認。ここで動かなければTriliumのフロントエンドスクリプトの設定・アクセス権を先に調べる。手動実行は成功するが自動起動は失敗する場合、`#run=mobileStartup` が効いていないか、モバイル起動状態が異なる可能性がある。

**注**：上記の簡易テストノートには `#run` は付けない。手動の実行ボタンからだけテストする。

## 画面が崩れた場合の復旧

- ☷でOFFにする
- またはURLに `?triliuiOff=1` を付けて再読み込み（他のクエリがあれば `&triliuiOff=1`）
- それでもダメなら **PCのTriliumからコードノートの `#run` 属性を外し**、Androidを再読み込み
- `#run` を外せば自動起動しない。既存ノート本文・DBは変更されない

## 実機で収集する最小情報

- Triliumのバージョン（例：0.xxx）、Android Chromeのバージョン
- コードノート登録：済／未、`#run=mobileStartup` 設定：済／未
- `?triliuiDebug=1` で表示された診断ステータス（またはバナーなし）
- スクリーンショット1枚（ノート名や個人情報は隠してよい）
- ☷の有無、左ナビゲーターと右編集領域の同時表示の有無
- 問題があれば画面回転・日本語入力時だけの現象か

この診断が通ってから、ノート階層切替、編集、画像、復旧をひとつずつテストする。
